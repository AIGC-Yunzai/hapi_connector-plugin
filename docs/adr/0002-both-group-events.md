# 群消息的两种事件都要处理

AstrBot 同时注册了 `GROUP_AT_MESSAGE_CREATE`（只被 @ 的消息）和 `GROUP_MESSAGE_CREATE`（群内全量，需在手机 QQ 里把机器人设为「获取群内全部消息」）两个解析器。本适配器照做：两个事件都接，是否真能收到全量由平台侧设置决定，代码不做假设。

## 这推翻了我最初的决定

先前记录过「只订 @ 消息、不做群内全量」，依据是 `q.qq.com/setup/` 给第三方客户端的提示：「暂未适配 QQ 群全量消息模式。请保持『获取群内全部消息』关闭，否则机器人可能无法正常接收和回复 @ 消息。」而 AstrBot 的文档推荐开启全量。

改判的理由：**接不接这个事件，与平台开不开全量，是两件事**。多接一个事件处理器不会让 @ 消息失效；不接则一旦用户按 AstrBot 文档开了全量，机器人就少一条消息来源。AstrBot 的实践也证明两者可以并存。所以把判断权交给用户，我们只负责两种都认。

## 仍然保留的取舍

群全量消息不做「必须 @ 才响应」的过滤，交由上层插件决定。原因是我们无法可靠区分「用户 @ 了机器人」与「用户只是说话了」——`mentions` 数组里 `is_you` 字段在部分事件形态下缺失，AstrBot 自己也要靠 `force_group_mention` 兜底。
